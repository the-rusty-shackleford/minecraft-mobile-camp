# C.A.M.P. 0.2.0 verification — 2026-09-20

The final Java 21 clean build passed all required gates: four JDK-only JUnit tests,
sixteen real-server GameTests, and the real-client booth. The client used Iris
1.8.14-beta.1, Sodium 0.8.13-beta.2 and Complementary Unbound r5.8.1. Master volume
was zero, and both the client and temporary Xephyr display exited afterwards.

The model audit inspected 28 block/item models and found zero equally facing,
positive-area coplanar overlaps, reduced from 341 before the edits.
The audit tool passed mypy --strict. Its scope is individual cuboid JSON models;
cross-block joins and appearance were inspected in the rendered captures, including
enlarged roof, control and module-icon crops. No remaining overlap artifact was
observed in those views. This does not claim every possible external shader setup.

## Reproductions and checks

- Rejected placement kept the server stack but sent no correcting inventory
  packet; the added regression failed against the old code. The fix prevents
  client prediction from consuming the carrier and explicitly resends unchanged
  inventory on rejection. Both hands and solid, wet and deep-footing failures
  preserve the named camp, module definitions and seventeen diamonds in nested cargo.
- The live client repeated all six rejected-placement cases through actual
  item-use packets, immediately retained the item, and saw no ghost core.
- Cancelled NeoForge placement retains cargo and releases both ledgers.
- Ordinary right-click on the blue deployed control opens the synchronized menu.
  Actual menu clicks detach and reattach storage with all seventeen diamonds.
  The new server test exposed that checking only SimpleContainer.canPlaceItem
  did not constrain vanilla Slots; the real slots now reject wrong items/bays.
- Actual night sleep on the bedroll preserves the previous spawn location.
  An ordinary bed still changes it. The initial fixture set night and attempted
  sleep in one tick; Minecraft's cached daytime flag was still true. Letting the
  real world tick after setting night corrected the fixture without relaxing
  normal sleep rules.
- All ten deployment strokes and all ten folding strokes were observed as
  vanilla moving-piston block entities. Actual redstone powers a moving module
  mount. A core save/reload mid-stroke resumes correctly. An occupant in the
  exterior actuator strip pauses and then permits assembly.
- Cancelling an internal piston stroke restores the entire reserved terrain,
  releases ownership/site reservations and returns one exact cargo-bearing item.
  Existing rotated cargo, storage/furnace roundtrip, terrain restoration,
  attachment protection and owner/occupant checks also pass.
- The real red switch folds the camp and produces exactly one pickup. Packed
  sneak-use still opens the module editor.

## Live deployment

Published v0.2.0 at release commit b3da7aa and deployed in pack 1.52.0 on
2026-09-20 alongside Schnappviecher 0.1.1. The downloaded GitHub asset and installed
server jar both match the SHA-1 above; the previous jar is absent.

The server received its 120-second warning at 21:28:23 UTC and subsequent countdown
reminders. Tool latency extended the countdown; each final reminder was honored.
The restart began at 21:31:51 UTC and reached Done at 21:32:01 UTC. Mod Hub reports
the server matches the published pack. Overall TPS was 20.000 (15.152 ms/tick).
Startup contains other mods' compatibility and recipe errors; no C.A.M.P.-specific
startup error was observed.

After deployment, Rusty requested removal of C.A.M.P. items from player inventories.
All four saved players were online; clear and its zero-count verification found no
C.A.M.P. items. Their inspected inventory, backpack and bundle contents contained
none. No world camps or chest contents were removed, and no ongoing crafting
enforcement was introduced.
