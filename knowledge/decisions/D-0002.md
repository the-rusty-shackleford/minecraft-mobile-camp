# One deployed camp per player, with a collapse control

Rusty added: "players should probably be restricted to only one C.A.M.P. at a time"
and "We need a built-in button or something that collapses the camp back down for
you to pick up". The implementation interprets the limit as one **deployed** camp
per player, across dimensions, including unloaded chunks and server reloads. Spare
packed items are allowed. This interpretation was stated in the conversation; it
does not claim a separate explicit answer about spare packed items.

A red switch on the exterior face of the core starts the reverse transformation,
then leaves exactly one packed item for pickup. Mining the core requests the same
operation. Only the owner or an operator can pack it; equipment remains usable by
other players. Living occupants must leave first. Ownership is released when the
site is restored and the packed item is created, not when folding begins.

The following implementation defaults were chosen under Rusty's instruction to
continue without routine approval interruptions. They are not quotations of prior
approval: an 8x8 footprint with six blocks of clearance for its pitched canvas roof;
four equipment bays; retained module inventories and cooking state; module changes
while packed; three-block maximum corner supports; clear loaded terrain; site
restoration; and protection of attached block identity.

The module boundary is a registered `ModuleItem` with an immutable definition of
parts in a 2x2x3 bay. Add-ons may register additional modules. It is a Java extension
point, not a datapack registry in this first implementation. Cargo uses each part's
stable local coordinate, so definitions should preserve those coordinates for saved
items. Modules carry their own cargo; removing a module never empties it into the
camp or the ground.

No deployment fuel is required. Furnace processing pauses while packed. Beds retain
vanilla location-based respawn behavior; sleeping after moving sets the new respawn
location. Unsafe-dimension bed use is refused without an explosion.

Recipes remain provisional. Rusty asked for the envisioned crafting requirements;
the response proposed a module-first chassis, two iron ingots plus leather as each
module's mounting materials, and the actual station blocks. That proposal has not
yet replaced the prototype recipes or received a separate balance decision.

This decision does not authorize publishing or deployment.
